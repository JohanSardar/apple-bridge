# Targeted migration tests

No scenario YAML is changed by these tools. The runner only supplies `--level sim`.

Build `cmd/bridge` with `-tags lab` and `cmd/bridge-lab` once into `bin/bridge` and `bin/bridge-lab` on `ssh build`, where Rust, Go and sccache are available. Cross-compile the Go binaries for Darwin there. The Air builds only the Darwin Rust gateway artifact with `CARGO_TARGET_DIR=~/ab-cargo-target cargo build`; every Air build and scenario command uses a short per-command `~/bin/ab-local` hold. Upgrade scenarios also require `bin/bridge-feed1` compiled from `world.LegacyRevision` for the target OS. `bin/bridge-lab build-legacy` builds that frozen revision using local Git history, and `make gateway-matrix` invokes it before running prebuilt scenarios. Missing prerequisites fail rather than silently using another binary.

Generate the map with `bin/bridge-lab inventory > /tmp/ab-inventory.json` and `python3 lab/testing/build_inventory.py /tmp/ab-inventory.json`. Inventory decodes all YAML without running scenarios, including stale web declarations rejected by the suite validator. Duplicate scenario IDs with different levels are combined in the map.

Run `make sim-parallel SIM_JOBS=4 SIM_OUTPUT=/absolute/new/run-directory`. The default excludes entries classified `run-at-end` in the selection map. Run those serially with `make sim-run-at-end SIM_OUTPUT=/absolute/new/end-directory` on each host. Explicit selectors may run either set for diagnosis. Add `SIM_SELECT=ab-state` or `SIM_SELECT=internal/state`. The equivalent Python runner accepts repeated `--select` arguments; these form a union. IDs, feature IDs, Go packages, Swift module names and proposed Rust crate names are selection keys. Unknown selectors fail closed. An unmatched or empty host selection is an error. Use the full suite when changing a shared harness, dynamic registration or a dependency absent from the map.

Set `APPLE_BRIDGE_IPHONE_ROOT` to the existing sibling iPhone checkout for its integration fixtures. Native fixture runs use `python3 lab/testing/sim_parallel.py --parallel 1 --output /absolute/new/native-run-directory`. The host filter defaults to the current OS; `--host all` explicitly attempts everything. Each Air scenario is automatically wrapped in `~/bin/ab-local`, releasing the shared lock between scenarios. The native worker records a monotonic start marker after acquiring the lock; per-scenario durations exclude that wait. Overall wall time includes queueing. Queue acquisition has a separate one-hour limit. Never run native SIM scenarios concurrently on the Air. A scenario filename ending REAL can still declare SIM membership; the level argument remains SIM.

Each scenario runs in its own process and creates its own harness World with random paths and ephemeral ports. Environment mutations are process-local. Builds are skipped only with explicit `--prebuilt`, and executables must exist. The parent applies a hard deadline (900 seconds by default, allowing the existing ten-minute relay-stream observation), sends TERM, allows ten seconds of cleanup, then kills the process group. Descendants remaining in that group are also killed on normal exit. Native builders that create their own process groups retain their own context cancellation behavior. Timeout is a failed verdict, never a pass. Raw logs stay in the specified private run directory; only IDs, verdicts and monotonic elapsed times enter `summary.json`. Wall time includes process startup and cleanup, excludes prebuilding and copying, and includes queueing between scenarios. Do not commit raw logs or rewritten scenario evidence.

The static map is conservative and inferred: feature modules plus imports from matching dispatch roots and their same-package helper closure, expanded through transitive product imports. Imports establish candidates, not executed product calls; conditional branches can overselect. P-class means a reachable harness file imports implementation packages, excluding contracts, or the native fixture route compiles/links product Swift modules. Calls to semantic contracts helpers (normalization, grants, operation descriptors, command validation/hashing, blob/effect interpretation) also count; the map records their names independently of the Phase 0 file classification. It is a conversion audit candidate, not proof that all those packages executed in-process. Swift modules are feature declarations, not SIM execution claims. Crate aliases follow FINAL-PLAN ownership. The map is an accelerator, not an authoritative coverage oracle.

`TEST-INVENTORY.md` records measurement gaps and proposed classifications. Merge suggestions require assertion comparison and owner approval; timing-sensitive gates belong at the end even when they have not demonstrated flakiness. Real sets are proposals only. None of these commands executes real scenarios.

Set `APPLE_BRIDGE_LAB_ROOT` to a private disk-backed directory when the host has a quota-limited `/tmp` filesystem. Worlds and legacy build staging use that root; the default remains `/tmp/ablab`. Logs and runner summaries use `SIM_OUTPUT` independently.

`make gateway-matrix` builds the Go lab binaries and the Rust `ab-runtime` bridge with `lab-queries` (including `lab-harness` and the default query fixtures), then selects the same default Linux SIM entries as `make sim-parallel`, using `--impl gateway=rust`. Run it on `ssh build`; `SIM_JOBS`, `SIM_TIMEOUT`, `SIM_SELECT`, `SIM_OUTPUT` and `RUST_BRIDGE` work as overrides. The target also builds `bin/bridge-feed1` from the frozen legacy revision; the checkout must retain that Git history. A failed gateway startup reports every entry as blocked without producing scenario qualification evidence. Runnable entries execute in parallel; remaining product imports and semantic-helper candidates are reported separately from execution results. Blocked and failed entries both make the target exit nonzero. `summary.json` records required feature packages and exact harness files. These conservative import candidates require a journey audit before qualification.

Portable Linux gateway SIM entries also pass a runtime inventory check: a declared non-P entry, nonempty audited code paths, no semantic helper candidates, and current source files without product imports/semantic calls. Missing or stale metadata fails closed. Existing owner-approved native allowances remain separate; this rule changes neither real nor Rust-replica qualification. The blanket Messages prefix exemption is removed. A CLI blocked verdict remains blocked in the parallel summary instead of appearing as an executed product assertion failure.
