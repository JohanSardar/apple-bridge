# Demo fixtures

Web scenarios use the seeded rich demo automatically. Set `web.huge: true` to expand `demo-chat-39` from 100 to 100,000 messages (104,900 total). CLI uses `bridge-lab demo --huge`; Go uses `demo.Options{Seed: 1, Huge: true}`.

POST `/demo-fixtures` to the browser control URL with `X-Bridge-Lab` authenticates exactly like `/incoming`. The response is a flat JSON object mapping native keys to captured record IDs: `ids["message-chat"]`, `ids["demo-message-00-000011"]`. It includes all 40 chats, 60 handles, and 200 showcase messages. Read aliases directly with `records.query` and `include_aliases: true` when additional messages are needed.

Native keys and generated bytes are stable across equal seeds. Bridge record IDs are allocated separately for each world. Dataset timestamps use the fixed `demo.Epoch`; use that instant for browser date-header fixtures.

Message 39 includes audio-message flags, a synthetic transcript and a generated waveform. The showcase group has a group-avatar attachment. Chats 35 and 36 have unknown senders; chat 36 is spam. Chat 34 and its messages are Recently Deleted. Receipt settings cover default, on and off. Pinning, muting, audio Keep, transcription and recovery deadlines are synthetic display fixtures; their presence does not imply that native Messages storage exposes them reliably.

Live Photo pairs are explicit dataset references from a still attachment to its movie attachment. SimApple rejects missing companions and enriches the still with a downloadable live video variant. Card payloads represent decoded fields, with synthetic URLs under example.com.

Huge mode is opt-in and may take over a minute under host pressure. Gateway browser projects each receive a fresh world; use a focused declared project for an opt-in performance scenario within the default scenario timeout.

Synthetic H.264/AAC clips are regenerated on macOS with `packaging/dev/heavy.sh swift lab/simapple/generate_media.swift`. Each one-second clip is under 50 KB. SimApple reports source geometry and presentation duration from the movie boxes; unparseable sources retain the 16×16 fallback with `dims_source: "sim-default"`.
