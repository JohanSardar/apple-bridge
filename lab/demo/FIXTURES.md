# Demo fixtures

Web scenarios use the seeded rich demo automatically. Set `web.huge: true` to expand `demo-chat-39` from 100 to 100,000 messages (104,900 total). CLI uses `bridge-lab demo --huge`; Go uses `demo.Options{Seed: 1, Huge: true}`.

POST `/demo-fixtures` to the browser control URL with `X-Bridge-Lab` authenticates exactly like `/incoming`. The response is a flat JSON object mapping native keys to captured record IDs: `ids["message-chat"]`, `ids["demo-message-00-000011"]`. It includes all 40 chats, 60 handles, and 200 showcase messages. Read aliases directly with `records.query` and `include_aliases: true` when additional messages are needed.

| Native key | Fixture |
| --- | --- |
| `message-chat` | Demo Studio showcase group |
| `demo-chat-01` | SMS, busy 1,000-message conversation |
| `demo-chat-02` | RCS |
| `demo-chat-39` | Performance chat |

Showcase keys follow `demo-message-00-NNNNNN`, with six decimal digits.

| Index | Content |
| --- | --- |
| 0 | Long text |
| 1–3 | One, two, three emoji |
| 4–5 | URLs, mention |
| 6–10 | Reply root, four nested replies |
| 11–13 | Edited with history, unsent, failed |
| 14–25 | Bubble and screen effects |
| 26–30 | Rename, add, remove, leave, group photo event |
| 32–45 | Media attachments |
| 42–45 | Four-image same-sender stack |
| 50–56 | Six classic reactions and emoji reaction, multiple senders |
| 57 | Removed reaction |
| 58–199 | Plain text runs |

Native keys and generated bytes are stable across equal seeds. Bridge record IDs are allocated separately for each world. The default clock is frozen at `demo.Epoch`.
