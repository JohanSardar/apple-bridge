# Real sensor qualification

Build and install the app after changing Swift code. Reuse that installation for subsequent runs. Set `APPLE_BRIDGE_REAL_DEVICE` to the physical device identifier from `xcrun devicectl list devices`, then run:

```
go run ./cmd/bridge-lab run lab/scenarios/iphone/APP-HEALTH-REAL.yaml --level real --json
```

The eight sensor scenarios launch the app with `--real-qualification <scenario> <fresh UUID>`. Each run holds `lockf -k -t 0 /tmp/ab-iphone.lock` until the result is copied or the deadline expires. Keep installations under the same lock when sharing the phone. The harness never builds or installs automatically.

The app writes a protected, atomic result in its Documents/qualification directory. Only the current UUID's final result qualifies. The host exports checks, counts and SHA-256 digests. Sample contents, media, location coordinates, Wi-Fi names and device names are excluded. Capture bytes stay in memory and are discarded; no Photos or recordings are created. Health writes use the existing tagged write/read/delete proof. The alarm uses a unique tagged identity, is scheduled an hour ahead, and is canceled immediately after readback. Screen Time uses a separate tagged store and monitor, clears them on exit, and preserves the existing selection and Bridge policies. Location removes its own tagged region.

Permission instructions are printed before launching. Allow up to three minutes per authorization step. The capture run permits two successive Face ID and sensor permission steps. A prompt instruction does not prove that a dialog appeared or that anyone tapped it. Record taps only when observed. No calls are made. NFC is explicitly skipped because the scenario requires a physical tag.

A successful API call is not complete acceptance proof. Empty Health reads fail because HealthKit hides read-denial status. Missing Wi-Fi information fails its check. Screen Time requires a selected test app, explicit shield/report observation confirmations and a nonce-bound monitor callback; authorization or registration alone cannot pass. Location qualifies the foreground fix and tagged geofence lifecycle; it does not claim background movement delivery. Capture qualifies Face ID, actual sensor bytes and discard; it does not claim a signed gateway round trip.

I1 automation instructions print to stderr and optionally append to `AB_IPHONE_AUTOMATION_STEPS`. They never ask Johan to tap. Run WDA on the physical UDID with `xcodebuild test`, forward its HTTP port, and set `AB_WDA_URL` and `AB_WDA_SESSION` to activate the app after each devicectl launch. Automate system consent and app observations through that session. Fresh partial receipts identify each sensor prompt phase. Health types requiring per-object access use a separate picker after bulk Health authorization. Each phase gets three minutes for authorization, with thirty seconds for process/copy overhead. A disconnect prints one waiting instruction and polls every 15 seconds until the same paired phone returns; reconnect time does not consume the tap window. The phone lock fails immediately if busy so another scenario can finish before retrying. Sensor probes run only in Debug builds. Keep the phone connected and unlocked; `unavailable` in `devicectl list devices` blocks both installation and qualification. An active tunnel can appear as `connected`; the structured result must also identify the same paired device.

Capture journals its capability preference before enabling it. Normal exit restores the journal; a timeout launches the existing restoration route and requires an acknowledgement bound to the run UUID. Later sensor and shell launches also recover a pending journal. A missing or stale acknowledgement fails cleanup rather than assuming success. Screen Time journals only its tagged run identity and recovers that named store/monitor on the next sensor launch. Health cleanup queries and removes only this app’s tagged samples, never another source’s records.

`APP-APPROVE-REAL` first exercises command approval and Face ID, then creates an isolated production OAuth pending request. Match its four-digit code, tap Allow and complete Face ID. Acceptance also requires the resulting authorization code to exchange for an authenticated token with exactly the requested scope. No external connector account is contacted. Temporary phone identity, capability switches, widget state and tagged delivery resources are restored and acknowledged separately.

`FOC-PHONE-SYNC` uses the shell receipt route and observes phone Focus status while the Air’s existing signed Mac helper enables and restores Do Not Disturb over iCloud. Run this scenario on the Pro with the physical phone selected. It acquires the Air’s `~/.ab-locks/app-focus` lock over `ssh -o BatchMode=yes air` before starting the phone observation, so queued Air work does not consume the phone’s observation window. The lock stays held through the phone restoration acknowledgement. The small Air-side step reuses `~/Applications/AppleBridgeDev/AppleBridgeHelper.app` (`com.johansardar.applebridge.services`), without building or requesting permissions. If that installation predates phone sync qualification, use `~/bin/ab-real` to prepare this branch on the Air first, then set `AB_REAL_FOCUS_AIR_HELPER` on the Pro to the absolute Air path of its signed helper. The override is passed as a quoted argument and must have the same service identifier; it never selects a Pro app. `AB_REAL_FOCUS_AIR_PACK` optionally selects the corrected signed `packaging/shortcuts/AB Focus.shortcut` on the Air. The helper imports and replaces only AB Focus through its existing Accessibility grant, then restores the prior foreground app and closes Shortcuts if the run opened it. Missing Accessibility fails without requesting it. The helper first checks an existing Focus grant and an inactive baseline; it does not request a new Mac grant. The Pro’s Helper and its Focus grant are not used. The AB Focus shortcut must already be imported and Share Across Devices enabled.
