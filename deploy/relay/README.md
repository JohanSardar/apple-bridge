# Relay deployment

Build `cmd/relay` for linux/amd64 with `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -p 4 -o ab-relay ./cmd/relay` on the Mac. Install as `/usr/local/bin/ab-relay`; create system user `ab-relay`, install config under `/etc/ab-relay` (directory 0750), then enable `ab-relay.service`.

The public ciphertext listener is 443. The authenticated TLS control API and outbound device tunnel share port 443 using control-host SNI routing. Configure `APPLE_BRIDGE_RELAY_URL=https://ab.lexaai.tech` on the Mac. `--control-acme` issues and renews the control certificate with the existing DNS-01 implementation. Its account and TLS keys remain mode 0600 under `/var/lib/ab-relay/control-tls/remote`; renewal runs every 12 hours when at most 30 days remain, and TLS adopts replacements without restart.

Cloud DNS uses Application Default Credentials from the VM service account. Project: `excerlock`; managed zone: `ab-lexaai-tech`. Required role if denied: `roles/dns.admin` on that zone (or equivalent custom permissions for record-set list/create/update/delete and changes create/get). The VM also needs the cloud-platform OAuth scope. The deployed ab-relay-dns service account already has the required IAM and scope.

Delegate `ab.lexaai.tech` from Cloudflare to the four name servers reported by `gcloud dns managed-zones describe ab-lexaai-tech --project excerlock`. The delegated zone now has apex, wildcard and control A records for 136.65.0.235. The apex is the trusted control endpoint; device TLS remains on the Mac. Cloud DNS publication waits for the exact TXT value at both public resolvers before accepting an ACME challenge. Each device receives an explicit A record copied from the zone wildcard in the same change as its first challenge; otherwise the challenge creates an empty DNS parent that suppresses wildcard A synthesis. Device A records persist across renewals. Cloudflare and other zones remain untouched.

ACME rate-limit override request: “Apple Bridge assigns a stable hostname per device under ab.lexaai.tech. End-to-end TLS keys are generated and retained on each Mac. Please raise the registered-domain issuance limit for our device enrollment service. We renew only within 30 days of expiration, reuse existing certificates and stable device names, and use Pebble/staging for tests. Expected device count and daily issuance volume: operator to supply before submission.”

Owner-only containment uses `-owner-keys-file /etc/ab-relay/owner-keys` in the systemd command. Create that operator-owned file with only the owner's canonical base64url Ed25519 public key, one key per line. Never copy a relay credential or private key into it. The binary validates configuration before listening and reads it again after signature verification on every enrollment or rotation. Missing, empty or invalid configuration denies admission; existing tunnel credentials remain usable. The legacy JSON state and request formats are unchanged. Keep the flag in the command during rollback: older binaries reject it and stop rather than silently reopening admission. For availability rollback use a previously verified gated binary; do not remove the flag to run an ungated binary publicly. Keep private copies of the prior binary, service definition and state, and retain the latest state across binary rollback so revocations and usage are not reverted.

Challenge admission permits 30 requests and enrollment/rotation together permit 20 requests per socket source per minute. Source tracking is capped at 4096 entries; unknown sources are refused while full. Forwarded headers do not establish source identity. This bounds unauthenticated admission independently of device quotas.

`RELAY-TLS-SPLICE` records the vulnerable relay/1 baseline using a synthetic local CA and genuine paired identities: the splicer observes a seeded feed marker after forwarding all four authentication frames unchanged. Wrong-name, untrusted-certificate and direct pinned mTLS controls reject the splice. Public relay/1 must not carry sensitive replica feeds pending channel binding. Pause affected replicas or configure direct pinned mTLS over a private route with no public reconnect fallback.

Until DNS authority moves off forwarding VMs, any retained permission to issue certificates for allowed hosts leaves operator interception possible. R0 limits admission and replica exposure; it does not make hosted browser TLS operator-proof. Abuse response, retention/deletion and operator visibility notices must be finalized before inviting tenants: the relay sees routing metadata, connection timing and aggregate ciphertext usage, while ordinary passthrough leaves application plaintext on endpoints. Investigate reports against the stable hostname, suspend before disconnecting, retain only necessary incident evidence, and disclose retention and deletion exceptions before launch.
