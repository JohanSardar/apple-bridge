# Apple data bridges and replication — 2026-10-16

**Finding:** No surveyed implementation documents the complete combination: broad Apple data, authenticated REST + MCP, durable full local replicas on arbitrary computers, command writes, and subsecond push. Macuse is the closest packaged remote-access product; iCloudBridge is the closest actual cross-platform synchronizer. These are findings from documentation/source inspection, not runtime certification. iMessage-specific bridges are excluded.

Dates below indicate observed repository activity, not support guarantees. **macOS 26 compatibility is unverified unless explicitly stated**; minimum-version claims alone do not establish it. “R/W” means exposed operations, not every native field. Private schemas and APIs require separate validation.

## Apple-data MCPs

Unless noted, these run on the Mac over local stdio; they provide request/response tools, not replicated databases.

- [Dhravya/supermemory apple-mcp](https://github.com/supermemoryai/apple-mcp): MIT; archived January 2026, last push August 2025. AppleScript/JXA bridges for Notes, Calendar, Reminders, Contacts, Mail, Maps. Contacts are principally readable; Notes/events/reminders support search/read/create rather than comprehensive CRUD. Useful adapter examples, weak foundation for a maintained product. [apple-mcp-pro](https://github.com/jasonpaulso/apple-mcp-pro) is an MIT May-2026 fork adding timeouts, SQLite Contacts reads and more tools; continuing maintenance unverified.
- [FradSer/mcp-server-apple-events](https://github.com/FradSer/mcp-server-apple-events), formerly **mcp-server-apple-reminders**: MIT; October activity; Swift EventKit CLI underneath TypeScript MCP. Calendar/reminder/list CRUD, but alarms/recurrence/location are currently read-only; “subtasks” are encoded in notes. Documents Tahoe toolchain/permission issues. Reuse native adapter patterns, not headline feature counts.
- [boutquin/apple-bridge](https://github.com/boutquin/apple-bridge): MIT; September activity. EventKit Calendar/Reminders CRUD; AppleScript Contacts writes and Notes read/create. Especially reusable: separate Swift packages for EventKit and Contacts.framework adapters. [orchard-mcp](https://github.com/l22-io/orchard-mcp) (MIT; June) combines EventKit, Contacts.framework reads and AppleScript/JXA app tools. [krmj22/macos-mcp](https://github.com/krmj22/macos-mcp) (MIT; August) uses EventKit, JXA Notes/Contacts R/W, SQLite Mail reads. [JonathanRReed/Apple-MCPs](https://github.com/JonathanRReed/Apple-MCPs) (MIT; October) offers EventKit, CNContactStore and AppleScript/JXA tools; network binds are rejected. All are adapter/tooling precedents. Contact-note fields require a restricted native entitlement or an AppleScript fallback.
- [rex/mcp-apple-reminders](https://github.com/rex/mcp-apple-reminders): MIT; October. SQLite reads, EventKit writes and private ReminderKit helpers extend into tags/sections/subtasks. Richer coverage trades away public-API stability; isolate any reuse. [remindctl](https://github.com/openclaw/remindctl) (MIT; October) is a reusable EventKit CLI rather than a replication service.
- Notes: [sweetrb/apple-notes-mcp](https://github.com/sweetrb/apple-notes-mcp) (MIT; October) combines SQLite/protobuf reads, AppleScript writes and Shortcuts for richer operations; explicitly handles macOS 26. [martijnstegink/apple-notes-reminders-mcp](https://github.com/martijnstegink/apple-notes-reminders-mcp) (MIT; September) explicitly reports Tahoe testing, dynamic NoteStore schema detection and persistent EventKit daemon. [ailenshen/apple-notes-mcp](https://github.com/ailenshen/apple-notes-mcp) (MIT; October) requires 26+, using SQLite reads and UI-assisted Markdown import. [evg4b/apple-notes-mcp](https://github.com/evg4b/apple-notes-mcp) (MIT; October) uses in-process ScriptingBridge. Reuse decoders/write strategies selectively.
- Older Notes MCPs: [sirmews/apple-notes-mcp](https://github.com/sirmews/apple-notes-mcp) (MIT; December 2024) exposes SQLite search/read tools. [RafalWilinski/mcp-apple-notes](https://github.com/RafalWilinski/mcp-apple-notes) (December 2024; license unverified) uses JXA extraction, local embeddings and LanceDB for read-oriented semantic search. Both offer indexing precedents; ongoing maintenance unverified.
- Remote-capable Notes: [CaseyRo/mcp-apple-notes](https://github.com/CaseyRo/mcp-apple-notes) (MIT; October), SQLite reads/AppleScript CRUD, HTTP MCP with bearer authentication; suitable narrow remote backend. [Orbit MCP](https://github.com/rusudinu/orbit-mcp) (September; license unverified) exposes EventKit Calendar/Reminders and AppleScript Notes/Mail R/W through authenticated loopback Streamable HTTP; not a supported remote replica system.
- [Peekaboo](https://github.com/openclaw/Peekaboo): MIT; active October development, documented macOS 26 fixes/CI. ScreenCaptureKit/Accessibility, screenshots and UI actions through CLI/MCP; useful fallback for unsupported actions, unsuitable bulk extraction/change capture. [macos-automator-mcp](https://github.com/steipete/macos-automator-mcp): MIT; archived September 2026; generic AppleScript/JXA execution, reusable scripts only.

## Remote access and actual synchronization

- **[Macuse](https://macuse.app/docs)**: commercial proprietary app, [October releases](https://macuse.app/changelog), macOS 13+; exact 26 validation unverified here. Broad R/W Calendar/Reminders/Notes/Mail, Contacts lookup and computer automation. EventKit/native frameworks, SQLite reads and AppleScript/JXA writes. Local MCP plus remote HTTPS tunnel, OAuth 2.1/API keys. No documented full replica/feed or data REST API; public HTTP release/license endpoints are different. Benchmark its onboarding, not code reuse: [terms prohibit derivatives](https://macuse.app/terms).
- **[cleverdevil/iCloudBridge](https://github.com/cleverdevil/iCloudBridge)**: MIT; January activity; macOS 14+. Swift/Vapor REST, EventKit Calendar/Reminders CRUD, PhotoKit photo reads, remote bearer tokens and selectable collections. Notes/Contacts/webhooks remain roadmap items. Closest permissive REST foundation; no durable client replication documented.
- **[tobydoescode/apple-bridge](https://github.com/tobydoescode/apple-bridge)**: October activity; license unverified. EventKit Calendar/Reminders CRUD, REST, remote-addressable MCP wrapper, read-only/read-write keys, launchd and web UI; macOS 14+. Strong functional match for two sources, without documented replica/change stream. Resolve licensing before reuse.
- **[keithvassallomt/icloudbridge](https://github.com/keithvassallomt/icloudbridge)**: GPL-3.0; October activity; macOS 13+. Actual two-way Notes↔Markdown and Reminders↔external CalDAV, plus Photos/password workflows. Notes uses AppleScript/Shortcuts/parser; Reminders uses EventKit. FastAPI/WebSocket reports sync progress; scheduled/manual jobs do not establish per-record push. Checklist write fidelity is limited. Reuse mapping/conflict lessons; account for GPL obligations.
- [plosson/apple-notes-api](https://github.com/plosson/apple-notes-api): MIT; October. Bearer REST Notes CRUD via AppleScript/JXA plus SQLite checklist reads; SSH/Tailscale deployment documented. [mac-agent-gateway](https://github.com/ericblue/mac-agent-gateway): MIT; September; authenticated REST/MCP over Reminders CLI commands. Both are narrow gateway precedents, not full replicas.

## Bypassing the Mac

**Calendar/Contacts:** iCloud CalDAV/CardDAV permit cross-platform reads and writes to iCloud calendars/events and addressbooks/vCards, subject to collection permissions. They do not expose “On My Mac,” other accounts or every Apple-specific field. [DAVx⁵](https://www.davx5.com/tested-with/icloud) (maintained Android client, GPLv3) verifies interoperability; [vdirsyncer](https://github.com/pimutils/vdirsyncer) (BSD-3-Clause; July activity) already provides two-way local `.ics`/`.vcf` copies. Reuse DAV libraries. ETags/sync tokens enable efficient delta polling; a supported general-purpose iCloud push subscription or subsecond SLA was **not verified**. These paths are OS-independent.

**Reminders:** upgraded primary-iCloud Reminders still do **not** work over CalDAV in 2026. [Apple's upgrade documentation](https://support.apple.com/en-nz/102457) and DAVx⁵ distinguish them from legacy/unupgraded reminders and external CalDAV accounts, which remain separate possibilities. Apple Reminders acting as a CalDAV *client* does not make upgraded iCloud lists CalDAV-accessible.

**Private iCloud APIs:** distinguish stale [picklepete/pyicloud](https://github.com/picklepete/pyicloud) (MIT; last push 2024) from maintained [timlaing/pyicloud](https://github.com/timlaing/pyicloud) (MIT; October). The latter documents Calendar create/delete, Contacts reads, Drive/Photos services, **[CloudKit Reminders CRUD](https://github.com/timlaing/pyicloud/blob/main/docs/services/reminders.md) and related alarms/tags/recurrence**, plus cursored changes. Its [Notes API](https://github.com/timlaing/pyicloud/blob/main/docs/services/notes.md) reads folders/text/attachments, renders/exports, and enumerates deltas; high-level Notes writes are not documented, and passphrase-locked notes raise an error. Cursors are pull, not push. [icloud-linux](https://github.com/chesnokpeter/icloud-linux) (MIT; June) wraps this as CLI/MCP. Real-account/ADP validation remains unverified here.

**Modern Notes are not an IMAP mailbox.** [IMAP-backed Notes accounts](https://support.apple.com/en-lamr/guide/deployment/depbd78ea978/web) remain possible, but cannot retrieve upgraded iCloud Notes. Public [CloudKit containers are app-scoped](https://developer.apple.com/icloud/cloudkit/designing/); ordinary CloudKit credentials do not authorize Apple's Notes container. However, [icloud-md](https://github.com/coddingtonbear/icloud-md) (MIT; October) reverse-engineers the private web CloudKit service for Linux/Windows/macOS bidirectional Markdown sync, three-way merges and history. Notes with non-table attachments are read-only; attachment uploads and continuous sync are explicit non-goals. Its [Obsidian plugin](https://github.com/coddingtonbear/obsidian-apple-notes) (MIT; young 2026 project) adds scheduled sync. Very relevant protocol/decoder reuse, experimental product dependency.

[icloud-headless-mcp](https://github.com/sjdonado/icloud-headless-mcp) (MIT; September) combines DAV/IMAP with persistent Chromium for Notes/Reminders R/W without a Mac. Its documented browser-backed calls take 60–90 seconds; no subsecond fit.

**Authentication/security:** [app-specific passwords](https://support.apple.com/en-us/102654) require 2FA, are revocable, and support Mail/DAV access; supported apps can alternatively obtain Apple-account authorization. Do not assume these credentials unlock private Notes/Reminders web APIs: browser sessions/2FA and reauthentication are separate. [ADP](https://support.apple.com/en-gb/102651) leaves Mail/Calendar/Contacts outside E2EE, but encrypts Notes/modern Reminders end-to-end. Web access is off by default and requires temporary trusted-device key approval. `icloud-md` explicitly says ADP likely must be disabled. Avoid making that concession a product prerequisite; a trusted Mac accesses its already decrypted authorized data.

## Notes and Screen Time on macOS 26

[apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser) (MIT; July commit) reads copied `NoteStore.sqlite`, decompresses `ZICNOTEDATA.ZDATA` protobuf and extracts formatting/attachments/tables. The live store is under `~/Library/Group Containers/group.com.apple.notes/`. It advertises iOS 9–26 parsing, **not blanket macOS 26 certification**. Device-passcode-locked notes remain unsupported. Use consistent SQLite backups including WAL state; never run its transforming pipeline on the live store. Combine parser knowledge with the explicitly Tahoe-tested MCP above. Apple confirms [no public Notes CRUD API](https://developer.apple.com/forums/thread/813810); AppleScript exposes partial HTML CRUD, not lossless rich-document editing. Full Disk Access and Automation grants are distinct.

[screentime-backup](https://github.com/alexjmiller5/screentime-backup) (September) captures knowledgeC, Biome streams and DeviceActivity summaries weekly. It reports **26.3+ vaulting of ScreenTimeAgent/DeviceActivity beyond Full Disk Access**, while knowledgeC/Biome remain readable; verified upstream on 26.1/26.3, not independently here. [screentime-dashboard](https://github.com/alexjmiller5/screentime-dashboard) (October) parses Biome SEGB app-focus events/cross-device summaries, with estimated durations flagged. Neither shows a reusable license: permission unresolved. [mac_apt](https://github.com/ydkhatri/mac_apt) (MIT; maintenance cadence/26 coverage unverified) offers Biome/ScreenTime forensic readers. These are read-only, incomplete historical evidence, not a full writable real-time Screen Time API.

## Replication candidates

These replicate **our normalized database**, not Apple-owned SQLite stores. Exact macOS 26 execution is unverified for all; server/container platform requirements differ.

- **[Electric](https://electric.ax/docs/sync/)**: Apache-2.0; October commits. Postgres logical replication→HTTP Shapes; [writes use your API](https://electric.ax/docs/sync/guides/writes). Good authoritative-read/command-write model, but adds Postgres/service and requires durable client materialization.
- **[PowerSync](https://docs.powersync.com/architecture/architecture-overview)**: October commits; Apache-2.0 SDKs, [FSL-1.1-ALv2 service](https://github.com/powersync-ja/powersync-service/blob/main/LICENSE), commercial edition. Backend CDC→persistent client SQLite; queued writes→your backend. Excellent semantic fit if PostgreSQL/another supported source database is acceptable; Apple adapter and command acknowledgement still ours.
- **[cr-sqlite](https://github.com/vlcn-io/cr-sqlite)**: MIT; August-2026 commit, wider maintenance uncertain. Native SQLite CRDT changesets, transport/auth supplied separately. Multiwriter convergence adds little when only the Mac commits authoritative state; cannot merge arbitrary Apple side effects safely.
- **[Litestream](https://litestream.io/reference/restore/)**: Apache-2.0; October commits. Object-store WAL/LTX backup with follow restoration/read-only VFS; polling, not general push/commands. Useful disaster recovery. **[LiteFS](https://github.com/superfly/litefs)**: Apache-2.0; latest default-branch commit April 2025 despite maintained/beta README. FUSE transaction replication/single writer; Linux deployment makes it awkward for native-Mac authority.
- **[libSQL embedded replicas](https://docs.turso.tech/features/embedded-replicas/introduction)**: MIT; October commits. Local files, forwarded SQL writes, explicit/periodic pull. Forwarded SQL bypasses Apple command semantics unless constrained. Vendor now recommends **Turso Sync** for new projects: MIT Rust engine, logical CDC and explicit push/pull; assess self-hosting, SDKs and change notification rather than assuming automatic push.
- **[Zero](https://zero.rocicorp.dev/docs/self-host)**: Apache-2.0; October commits. Postgres→zero-cache→client query replicas and custom mutators. Good reactive-app infrastructure, weaker fit for arbitrary full local SQL databases; extra services.
- **[NATS JetStream](https://docs.nats.io/concepts/jetstream)**: Apache-2.0; October development; native cross-platform broker. Durable replay/consumer cursors and command/reply transport; best lightweight infrastructure candidate here. SQLite projection, snapshot bootstrapping, retention recovery, authorization and idempotent application remain ours; at-least-once delivery requires deduplication.

## Recommendation

Reuse permissive EventKit/Contacts adapters, Tahoe-tested Notes decoders and existing MCP SDKs; evaluate NATS plus SQLite or PowerSync before building delivery machinery. Build the missing product layer: normalized snapshots, ordered durable changes/tombstones, resumable replicas, idempotent commands, reconciliation and per-device authorization/encryption. Bearer-authenticated HTTP requires TLS or an encrypted tunnel for remote use; local replica encryption and credential revocation remain separate requirements.

Keep Mac authority as the default: it includes local/non-iCloud accounts and preserves ADP on iCloud; ADP does not protect exported replicas. Offer DAV Calendar/Contacts as an optional Mac-free connector; private CloudKit/browser paths are experimental alternatives. Promise subsecond propagation **after Mac ingestion**, subject to measurement—not iPhone-to-replica latency. Apple's [EventKit notification](https://developer.apple.com/documentation/eventkit/ekeventstorechangednotification) invalidates objects without identifying changes; [Contacts](https://developer.apple.com/documentation/contacts/cncontactstore) offers history tokens. Neither removes iCloud delays, sleep or Notes polling/schema limits. “Full” and “built for everybody” need explicit per-source fidelity and permission boundaries.
