**iMessage bridge landscape — researched 2026-10-16**

No reviewed project establishes the complete requested combination: all history, every operation, lossless replication, subsecond latency, strong security, and consumer-ready installation. Findings below distinguish documented capabilities from runtime verification: no Mac/device tests were performed. “History” generally means data available on the host, including downloaded attachments, rather than guaranteed recovery of everything in iCloud.

**BlueBubbles server + helper.** The most complete existing self-hosted REST reference. Reads `chat.db`: history, media, reactions, replies, edits/unsends and delivery/read timestamps. Basic writes use AppleScript for text/files and direct conversations. Its [private helper](https://docs.bluebubbles.app/private-api) adds targeted tapbacks, threaded replies, edit/unsend, typing send/receive, read/unread, group creation/rename/photo/membership/leave, effects, subjects, mentions, deletion, Focus/notify-anyway, availability checks and attachment retrieval. It calls private IMCore inside Messages; [installation](https://docs.bluebubbles.app/private-api/installation) requires disabling SIP and library validation. Basic database access/AppleScript does not require disabling SIP.

Realtime uses [filesystem monitoring](https://github.com/BlueBubblesApp/bluebubbles-server/blob/v1.9.9/packages/server/src/server/lib/MultiFileWatcher.ts), sockets and [webhooks](https://docs.bluebubbles.app/server/developer-guides/rest-api-and-webhooks); transient typing comes from the helper. Security: Full Disk Access (FDA), Automation, shared server password passed in URL parameters; TLS/WSS and optional third-party tunnels/Firebase. This needs stronger device-specific authorization for our product. Both repositories are Apache-2.0, reusable. Latest stable [server 1.9.9](https://github.com/BlueBubblesApp/bluebubbles-server/releases/tag/v1.9.9) is 2025-05-16; [helper 0.0.21](https://github.com/BlueBubblesApp/bluebubbles-helper/releases/tag/0.0.21), 2024-11-19. Development continues in 2026; a rewrite is underway.

**BlueBubbles on macOS 26: not a blanket compatibility pass.** [#777](https://github.com/BlueBubblesApp/bluebubbles-server/issues/777) remains open: Tahoe's `any;-;` GUID prefix becomes an invalid AppleScript service constant, producing `-1700` in the fallback send path. The report has SIP enabled; this is separate from private-helper failures. Suggested normalization is not proof of a released fix; users still reported failures October 8. [#814](https://github.com/BlueBubblesApp/bluebubbles-server/issues/814) reports threaded private sends hanging on 26.5.1/1.9.9 although plain sends work. [Helper #59](https://github.com/BlueBubblesApp/bluebubbles-helper/pull/59) proposes a Tahoe typing-item crash fix and remains open.

**AirMessage.** [Server](https://github.com/airmessage/airmessage-server) reads local history/attachments, reactions and receipt state; sends text/files to individuals/existing groups. New groups on modern macOS use `NSSharingService` plus UI submission, rather than a full management API. No comparable edit/unsend/tapback/typing/group-management write surface. SIP stays enabled; FDA/Automation and GUI access are needed. [Database scanning](https://github.com/airmessage/airmessage-server/blob/main/AirMessage/Database/DatabaseManager.swift) runs every **two seconds**, missing the latency requirement. Password-derived [AES-128-GCM](https://github.com/airmessage/airmessage-server/blob/main/AirMessage/Connection/EncryptionManager.swift) protects relay traffic; Connect adds account/relay infrastructure. Apache-2.0, reusable but stale: [4.1.4](https://github.com/airmessage/airmessage-server/releases/tag/v4.1.4), 2022-10-19; last main commit 2022-10-20. Tahoe compatibility unverified.

**mautrix-imessage / Barcelona.** [AGPL-3.0 Matrix bridge](https://github.com/mautrix/imessage), updated 2026-05-14; no GitHub release. Its [matrix](https://github.com/mautrix/imessage/blob/master/ROADMAP.md) distinguishes basic `chat.db`/AppleScript, SIP-disabled Barcelona private-framework backend, and BlueBubbles backend. History/backfill, media, replies and receipts are readable, but reaction backfill is missing. Basic writes: text/files; Barcelona adds reactions/replies/typing/read receipts but lacks edits/unsends; BlueBubbles supplies those. Basic [fsnotify database events](https://github.com/mautrix/imessage/blob/master/imessage/mac/messages.go), backend notifications and Matrix/WebSocket transport supply live updates. Barcelona is explicitly unmaintained; Tahoe unverified. The bridge processes plaintext even when Matrix rooms are encrypted. Useful reference; copyleft complicates proprietary incorporation.

**Beeper's historical approaches / pypush.** Original Beeper used Mac relays; its October 2023 Cloud bridge and December Mini instead [reimplemented Apple's protocol](https://blog.beeper.com/2023/12/05/how-beeper-mini-works/), using persistent APNs connections, device registration and endpoint encryption. This was a messaging endpoint, not a complete Mac-history replication API. Apple disruptions led Beeper to [stop chasing outages](https://blog.beeper.com/2023/12/21/beeper-moving-forward/). [beeper/imessage](https://github.com/beeper/imessage) is archived, AGPL-3.0; last commit January 2024, registration providers required. Current [pypush](https://github.com/JJTech0130/pypush) is **SSPL**, not a ready iMessage SDK: its rewrite currently restores APNs only. [2.0.2](https://github.com/JJTech0130/pypush/releases/tag/v2.0.2), 2026-03-15. Protocol research references; unsuitable default dependencies.

**New Beeper platform-imessage: important counterexample.** [MIT Swift library/CLI](https://github.com/beeper/platform-imessage), [0.24.8](https://github.com/beeper/platform-imessage/releases/tag/v0.24.8) September 24; main updated October 15. Reads local messages and rich metadata; uses Automation/Accessibility to send text/files, create DMs/groups, target replies/reactions, edit/unsend, mark read/unread and send typing **with SIP enabled**. Claims ~95% Tahoe parity. [Database/WAL file events](https://github.com/beeper/platform-imessage/blob/main/src/IMessage/Sources/IMDatabase/Database/IMDatabase.swift) debounce at 25 ms; this is not an end-to-end guarantee. Local permissions, no library network transport. [TODOs](https://github.com/beeper/platform-imessage/blob/main/todos.md) retain group management, rich sends, cross-process coordination and local-deletion synchronization gaps. Strong advanced-action foundation candidate; REST/MCP/replication must be built.

**Steipete → openclaw/imsg.** [MIT Swift CLI/core](https://github.com/openclaw/imsg), [0.17.0](https://github.com/openclaw/imsg/releases/tag/v0.17.0), October 16. Read-only SQLite history/media/reactions; database/WAL events with polling fallback; NDJSON/stdio JSON-RPC, easily wrapped by REST/MCP or SSH. Normal text/files/new recipients/existing groups use AppleScript; standard UI tapbacks lack guaranteed GUID targeting. FDA/Automation, optional Contacts/Accessibility; no network authentication layer itself. Tahoe supported with explicit ghost-send diagnostics. Optional [injected IMCore](https://github.com/openclaw/imsg/blob/main/docs/advanced-imcore.md) supplies mutation, rich replies, typing/read receipts, polls, stickers and group operations, requiring SIP off; Tahoe library-validation/entitlement gates remain. Best basic transport dependency; advanced path is explicitly unstable.

**Photon.** [imessage-kit](https://github.com/photon-hq/imessage-kit), MIT [3.0.0](https://github.com/photon-hq/imessage-kit/releases/tag/v3.0.0), April 20; June activity. Local SQLite querying and [WAL watching](https://github.com/photon-hq/imessage-kit/blob/main/src/infra/db/watcher.ts); AppleScript text/files/existing-group sends, FDA/Automation, SIP enabled. Tahoe GUIDs documented; no exhaustive Tahoe certification. Reusable basic TypeScript SDK. [Advanced kit](https://github.com/photon-hq/advanced-imessage-kit) exposes edits/unsends, replies, reactions, typing, group operations, polls, scheduling, stickers and rich text, but is deprecated. Successors [Spectrum](https://github.com/photon-hq/spectrum-ts) 12.12.0 (October 16) and [advanced-imessage](https://github.com/photon-hq/advanced-imessage-ts) 2.3.0 (October 14) offer MIT clients, token-authenticated HTTP/webhooks and gRPC event streams. [Photon 2.0, announced October 15](https://photon.codes/blog/introducing-photon-2.0), explicitly describes its macOS cluster, Apple Account registration and Astrolabe state-management layer; claims around 100 ms in vendor measurements. Private-framework/injection details, SIP policy and complete historical coverage remain unverified; open SDKs do not establish an open, independently deployable advanced server.

**ReagentX imessage-exporter.** [GPL-3.0 Rust exporter/database library](https://github.com/ReagentX/imessage-exporter), [4.3.0](https://github.com/ReagentX/imessage-exporter/releases/tag/4.3.0), September 15; active September development. Comprehensive local parsing: attributed bodies, multipart messages, threads, edit history, tapbacks/stickers, effects, app payloads and attachments; supports Tahoe and claims newer schemas too. Read-only, FDA, SIP enabled, local/offline; no sends or realtime stream. Best history-format reference, subject to copyleft before code incorporation.

**MCP ecosystem.** [mac_messages_mcp](https://github.com/carterlasalle/mac_messages_mcp), MIT [1.1.0](https://github.com/carterlasalle/mac_messages_mcp/releases/tag/v1.1.0), September 1; October activity. Read-only Messages/Contacts queries and attachment access, AppleScript direct/group/file sends and in-process scheduling; default new-message polling is one second. Local stdio/FDA/Automation, SIP enabled; [security policy](https://github.com/carterlasalle/mac_messages_mcp/blob/main/SECURITY.md) explicitly leaves send approval to clients. No full advanced mutation suite; Tahoe not explicitly certified.

[iMessage Max](https://github.com/cyberpapiii/imessage-max), MIT 1.8.0 October 12, adds Swift read/search/media/send tools and caller-driven cursor polling. SIP-enabled SQLite/AppleScript, FDA/Automation; sends execute immediately and rely on client approval, while remote authentication was not verified. [genericService](https://github.com/genericService/imessage-mcp-server), MIT 1.15.1 October 14, adds HTTP/SSE, OAuth/Bearer auth, SQLite reads, imsg/AppleScript sends and SIP-disabled bridge edits. Filesystem triggers plus five-second fallback drive content-free, HMAC-authenticated webhook wakeups; edit/deletion index reconciliation runs every ten minutes. Both are reusable wrappers; exhaustive Tahoe/security validation unverified. [Anthropic's channel](https://github.com/anthropics/claude-plugins-official/tree/main/external_plugins/imessage) similarly uses one-second database polling/AppleScript and access lists, SIP enabled; current licensing/release/Tahoe guarantees not verified.

**New direct-protocol alternatives.** [OpenBubbles/rustpush](https://github.com/OpenBubbles/rustpush), updated October 12, implements private Apple protocols/APNs without Messages injection; SSPL with an OpenBubbles-specific exception. [Corten-Matrix](https://github.com/lrhodin/corten-matrix), MPL-2.0 wrapper, [1.3.5](https://github.com/lrhodin/corten-matrix/releases/tag/1.3.5) October 9, claims media, reactions, edits/unsends, groups, typing/receipts and CloudKit backfill. It needs Apple credentials/device validation; Contact Key Verification must be disabled. No SIP bypass, but no verified Tahoe feature matrix or latency SLA. Consider experimental references; investigate dependency licensing and credential security before reuse.

**Commercial APIs.** Sendblue, LoopMessage and Linq expose provisioned sender history and webhooks, not demonstrated imports of an owner's full existing Apple account. Live documentation confirms 2026 activity; backend release dates/macOS versions are undisclosed. Services below are proprietary unless stated otherwise.

- **[Sendblue](https://docs.sendblue.com/api-v2):** text/media, history queries, groups/membership/naming, reactions, typing and read receipts; native edit/unsend not verified. [Security](https://docs.sendblue.com/security/) documents API-key/secret headers, TLS, encrypted storage and webhook shared secrets. Exact Apple hardware/private-framework/SIP implementation is unverified. Depend via contract, not reusable backend code.
- **[LoopMessage](https://loopmessage.com/apidocs/send-message):** text/media/voice, replies, reactions/effects, typing/read status, edit/unsend and existing groups; explicitly cannot create/rename groups or change members. HTTPS API keys/webhooks; attachment URLs must be publicly reachable. Hardware/framework/SIP implementation and full-history export unverified. Commercial dependency only.
- **[Linq](https://linqapp.com/blog/send-imessage-programmatically):** explicitly operates Macs/Apple accounts behind REST/webhooks. [V3](https://docs.linqapp.com/) covers history, rich messages, edits, groups/members, reactions, typing/receipts, polls and stickers. [Delete](https://docs.linqapp.com/channel/imessage/api/resources/messages/methods/delete/) removes API data, **not unsending**. Tokens and optional [zero-retention](https://docs.linqapp.com/channel/imessage/guides/platform/zero-day-retention/) controls; advertised <120 ms is not independently measured full-sync latency. Internal injection/SIP choices unverified; commercial dependency only.

**Closer commercial/product matches.** [autoMessage](https://automessage.app/docs/api/) runs on the owner's Mac/Apple ID, reads local SQLite into a cloud copy, and offers paginated conversations/messages, queued sends, drafts, contacts, REST, MCP and webhooks. Sent-message editing, unsend, reactions, typing and group-management writes are not established by its published endpoint list. [Security claims](https://automessage.app/security/): FDA/Automation, notarized hardened app, per-owner storage rules, TLS/at-rest encryption and signed webhooks. Its [hosted MCP](https://automessage.app/docs/mcp/) permits an API key in the URL. SIP policy, actual event latency, Tahoe support, complete-history fidelity and latest binary version are unverified. Closest packaging reference; closed backend, commercial dependency.

[MessageBlue](https://docs.messageblue.ai/api-reference) documents gateway-to-Mac agents, history analytics, text/media/voice, groups, tapbacks, typing/read receipts and signed inbound/status webhooks. Request HMAC includes timestamp/nonce and replay rejection. Full edit/unsend/group administration, source license, client releases and Tahoe/SIP details unverified; commercial/private-deployment reference. [Tuco](https://tuco.ai/blog/tuco-ai-vs-sendblue-complete-comparison) explicitly provisions a dedicated Mac mini/Apple ID per customer; its internal automation/SIP implementation and full-history API remain unverified. These findings do not establish that Sendblue or LoopMessage use the same architecture.

**Decision.** AppleScript supports basic sends; local SQLite provides history without SIP changes, but its schema is not an Apple-supported history API. [Messages extensions](https://developer.apple.com/documentation/messages/msconversation) do not provide arbitrary account-history access. **No requested user-visible action is proven inherently SIP-only:** Beeper demonstrates advanced UI automation. Direct IMCore operations require private APIs and, in the reviewed injected implementations, reduced protections; reverse-engineered network clients need private protocols but not necessarily SIP changes. Group UI automation remains possible even where a library hasn't implemented it. Apple's [limits](https://support.apple.com/en-ie/guide/messages/ichtd68328c6/mac) remain: unsend within two minutes, edit five times within fifteen minutes, plus [membership constraints](https://support.apple.com/en-ie/108303).

For direct framework automation, the private surface includes GUID-targeted replies/reactions, edit/unsend, typing subscriptions/emission, marking read, group mutation, effects/mentions/subjects, native voice/sticker/poll payloads and forced attachment downloads. This describes the implementations reviewed, not proof that each action is impossible through public Accessibility. Reading received reactions/replies/edits/receipts from disk does not itself require the private helper.

Replication needs more than a new-row cursor: edits, receipts, unsends and deletions mutate existing state; database replacement invalidates cursors, and transient typing is not historical data. [imsg watch](https://github.com/openclaw/imsg/blob/main/docs/watch.md) documents database-generation cursors and best-effort, nonresumable helper events. All bridges read decrypted endpoint data; inference: TLS alone does not extend Apple's end-to-end encryption to our replicas. GUI automation also needs coordination with the owner's actions.

Recommendation: imsg for baseline transport, Beeper for SIP-enabled advanced actions, BlueBubbles for deepest REST/private-API reference, exporter for parsing. Build authenticated device pairing, encrypted replicas, scoped MCP writes, durable change reconciliation and measured latency separately. No existing foundation justifies promising every feature and <1 s for everybody.
