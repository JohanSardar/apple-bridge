## Phase 4 G-D1: OAuth and consent integration

`ab_trust::oauth` exposes `Client`, `Code`, `Exchange`, `Tokens`, `agent_grants` and Authority methods `register_oauth`, `oauth_client`, `create_oauth_agent`, `issue_oauth_code`, `exchange_oauth`, `authenticate_oauth`. `authenticate_token` now recognizes agent and OAuth tokens as well as ordinary tokens. OAuth storage retains Go's credential envelopes, and every rotation happens under the existing credential file lock. Access principals retain level, grants, resource and access expiry; existing authorization adapters must enforce resource audience. Refresh reuse persists family revocation before returning unauthorized.

`ab_trust::devices` exposes Go-shaped `Session` and Authority methods `create_device_session`, `authenticate_device`, `create_web_enroll`, `check_web_enroll`. `ab_trust::passkeys` exposes Go-shaped `Passkey`, core ceremony start/registration and Authority passkey persistence/login verification. The fixed handle is `apple-bridge-owner`.

`ab_frontdoor::web::Web::new(authority, bound_address, public_host, approvals).router()` owns the server-rendered routes. Keep its handler separate from API bearer middleware. Runtime marks a genuinely TLS-authenticated connection using `SecureTransport`; never infer this from a request header. Local HTTP cookies are `ab_session_local`, TLS cookies `__Host-ab_session`. `Approvals` is a synchronous adapter for `pending`, `command(id)` and `decide(owner,id,approve)`; it must perform current command-authority authorization and expiry processing. The web handler runs synchronous work off Tokio workers. Approval rows contain `command_id`, `operation`, `principal`, preformatted redacted `arguments`, and `owner_arguments`. `pending_connectors`/`decide_connector` expose the separate local connector-control interface for runtime wiring.

G-D1 algorithm policy is now explicitly ES256/P-256 and EdDSA/Ed25519 (ADR 0027 addendum). `passkeys::validate_home(home)` validates all stored RP IDs without writing; `Authority::open` calls it before initialization and `inspection::doctor` calls it before database inspection. Unsupported keys return `Error::UnsupportedPasskey` with a re-enrol hint. G-F must preserve this error text and must not filter incompatible keys.

G-F assembly contract: construct Web after binding the listener so its port matches the serving origin, provide the actual public hostname and an Approvals adapter backed by the single command authority. Mount Web outside API bearer middleware; mark SecureTransport only at actual TLS termination. `pending` and `command` return current rows; `decide` must reauthorize owner, enforce expiry/hash/state and delegate to the common command authority. Mount pending_connectors/decide_connector only in the owner control channel. G-D1 owns auth/pages and exports these adapters; G-F owns gateway listener, CLI, command authority adapter and ingress assembly. The consent fixture qualifies Rust auth/pages against a Go backend, not the assembled Rust gateway.


## G-F assembled binary findings

WEB-AGENT-OAUTH reaches the selected Rust gateway after owner enrollment; missing/invalid bearer responses on /mcp and /v1/op/messages.chats lack the Go WWW-Authenticate discovery challenge. Frontdoor::guard currently returns problem(error) directly. G-D owns challenge/metadata behavior; please expose it through the common guard using the verified request origin, without trusting caller headers for transport security.

WEB-AGENT-ACTIVITY reaches the binary but Frontdoor::AuditEntry has only principal/method/matched route/status, so the runtime adapter cannot record operation names, argument hashes/bytes or denied command IDs. G-C/G-B activity integration needs a public operation/command audit sink at Service/LocalGateway boundaries; runtime already installs QueryActivity for native queries. Do not derive semantic records from the generic HTTP audit row.

LAB-SSE does not reach heartbeat scanning on the Rust gateway: the existing openSSE helper sends an empty Last-Event-ID header. changes treats that empty header as a cursor and returns 409, while Go treats it as no cursor and returns 200. An instrumented unchanged binary journey confirms Rust 409 followed by the Go replica's 200 and three correctly spaced heartbeats. Filter empty header values before parse_event_id, preserving nonempty stale-cursor Reset behavior. This belongs at the common Frontdoor boundary; do not strip the header in a runtime-only wrapper or weaken the fixture.
