# G-E binary fixture contracts

G-E owns the lab adapters, not product authority/operations/runtime. The existing generic `binary_harness_required` verdict must remain until each scenario actually drives its selected binary. CLI returns typed JSON; private fixture data remains in disposable homes.

Available and consumed: `agent create|list|revoke --home <home>`, with create returning `{"agent":...,"token":"..."}`; runtime IPC and API listeners; GET `/v1/openapi.json` for schemas. Mac SIM assertion bodies now inspect the binary's schemas and command responses; the lab owns the readback predicate. Six baseline P/D files have had their semantic-helper/trust dependencies removed, with shared SIM paths proved on Go. Their real branches are not qualified by SIM. AUTH-SCOPES-METADATA also drives the binary token CLI and metadata HTTP routes against the frozen OAuth scope corpus. Concurrent activity agents are created through the selected binary CLI; the enclosing owner-session fixture still requires the device-session seam.

Still required from owners for the remaining baseline P/D journeys:

- **Trust/web:** create an owner device session at a specified access path (`trusted`/`public`), return token and device ID, enumerate/revoke sessions, enroll passkeys and set fixture expiry. This blocks `agent_access`, `web_server`, `agent_activity`, web cookie/auth/host/upload journeys. Driving normal web enrollment is also acceptable if both binaries expose a fixture-safe ceremony without prompts.
- **OAuth:** equivalent binary setup and exchanges for `CreateOAuthClient`, authorize/code/refresh rotation and revocation, including expired client/principal cases and CIMD metadata. `agent_oauth_*`, `security_oauth`, `security_owner` currently execute Authority methods directly.
- **Delegation:** generate/verify deliberately expired, revoked and scope-expanded delegated identities through selected binary boundaries; retain existing negative assertions in `delegation`, `security_remote`, `agent_level_boundaries`.
- **iPhone:** selected-binary pairing, delivery and ingest fixture endpoints preserving APP/health/location assertions. The `ab-iphone` crate interface alone does not qualify a runtime journey.
- **State/blobs:** supported execution seams for in-process State/Blobs constructors (`search_perf` and upload fixtures). `snapshot_pool` already drives the feed binary. The blob journey uses frozen-schema offline SQL fault injection followed by selected-binary restart/migration; its post-migration inspection is read-only. Do not replace these with writable Go State constructors against a Rust home.

Shadow capture replay now records and replays authenticated POST `/v1/op/*` admissions and response boundaries. Full live qualification additionally needs every command ingress (MCP, replicated admissions, approval decisions, iPhone), replayable credentials, and a lab-only deterministic clock for expiry/recovery if wall-clock decisions must be reproduced. Explicit deadlines and their request hashes cannot be silently rewritten. New bridge IDs in opaque record data/command arguments remain exact and can still cause unexplained differences; the comparator only aligns identity envelope fields and the alias partition. An implementation-owned deterministic ULID seam is needed for sources embedding allocated IDs in opaque data, unless a narrower reviewed comparison contract is supplied. G-E must not change product randomness or frozen persisted formats to force parity.

### Offline replay isolation requirement

Loopback listener flags do not disable saved replica dials, pairing retries, remote ingress adapters or phone pushes. Replay now requires a Linux network namespace with only loopback and fails rather than falling back to host networking. It refuses nonempty saved `remote/` directories: Tailscale/control Unix sockets can reach host services despite network isolation. No snapshot credentials or persisted rows are silently rewritten to make a home acceptable. The host-loopback sentinel/isolation proof and synthetic command replay run on disposable homes only.

Runtime/remote owners must provide a lab-only offline replay mode that disables host adapter access, external helper launch, remote ingress/phone pushes and background pairing/feed dials before homes carrying those configurations can be replayed. It must keep state, ledger, principal and command identities intact and bind only explicit isolated listeners. Current live-run qualification remains blocked on that mode, all-ingress admission observation, deterministic decision clocks/identity allocation, and the cross-language not_found admission divergence. No live tap is authorized by these changes.

### Selected binary operation catalog for lab scope/schema assertions

`bridge lab-operation-catalog --home <isolated-home>` is a lab-build-only, read-only JSON fixture command. It returns an object keyed by operation name, each value `{"scope":"messages:write","schema":{...}}`, populated from that selected implementation's actual registered scope and operation input schema. It must not open/migrate a home or start a gateway/Helper. The Go lab build exposes it through its existing lab probe registration. Rust runtime should expose the same command under its lab harness feature, using its catalog; no Go fallback is allowed.

The unchanged Messages capability descriptor assertions consume this output, retaining actual scope equality and nonempty-schema checks. Public OpenAPI does not expose operation scopes, so substituting a frozen expected scope or weakening that predicate is not sufficient. The remaining native Messages owner/WebSocket fixtures are still unqualified. Private Go-only attempts show WEB-MSG-REAL-READ fails authenticated_web_socket with both the previous authority setup and a normal owner enrollment; the unrelated enrollment-URL repair attempts were reverted. No real-level scenario was run.

The capture-prefix raw-data discrepancy is nested `coverage` key ordering for contacts/messages/shortcuts. Go `internal/state/source.go:SourceState` marshals a map containing the typed Coverage struct, retaining its field order. Rust `ab-state/src/protection.rs:source_state` builds JSON and sends it through generic data normalization. Parsed values match, but raw order differs, so reopening a Go snapshot introduces a byte change and version bump. This is an owner investigation lead supported by the byte comparison, not permission to canonicalize record data in the diff.

The catalog probe uses a distinct disposable home path and verifies that the command leaves it absent, so an unsupported CLI cannot rewrite the running test gateway's authority. Focused Go capability assertions pass with that absence check. On the tested Rust assembly, snapshot pool, Messages self-test/incoming/file send pass; consent fails ordinary owner enrollment and capability metadata fails the nine descriptor checks because the catalog command is missing. The full default Go suite remains 201/201 with all 150 focused named assertion verdicts unchanged.
