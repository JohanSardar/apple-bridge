# Relay routing and enrollment (G2-1 / G2-2)

`cmd/relay --zone relay.example.com --control-cert control.pem --control-key control-key.pem` listens on `:443` for public TLS and `127.0.0.1:8443` for the separate HTTPS control API. `--addr` and `--control-addr` permit test ports. The control certificate belongs only to the control API. Device origin keys never enter the relay. `APPLE_BRIDGE_RELAY_ADMIN` enables the operator policy API; keep it in protected service configuration.

The public listener accepts only a bounded, visible TCP TLS ClientHello. It reads up to 64 KiB across handshake records with a five-second deadline, finds the enrolled SNI, and forwards the original bytes unchanged. Unknown names and malformed or absent SNI close. After admission, `--idle-timeout` (default two minutes, positive) closes both sides and releases the device slot if neither ciphertext direction makes progress. Reads and writes in either direction renew the inactivity deadline, including streams still negotiating TLS; active one-way streams remain supported. Configure `Server.IdleTimeout` before serving when embedding the relay. Every listener exit cancels forwarding and closes public and tunnel connections before waiting for workers. A global 256-connection admission bound also covers slow handshakes. HTTP/3 and encrypted routing SNI are outside this protocol.

Enrollment uses Ed25519 public keys encoded as unpadded base64url. Obtain a single-use nonce from `GET /challenge` (one minute, at most 4096 outstanding), then `POST /enroll` with `public_key`, `nonce`, and `signature`. Sign `apple-bridge-relay-enroll\n<zone>\n<nonce>`. Optional `hostname` may only name the same key's existing assignment. Successful enrollment returns `hostname` and `credential`. Re-enrollment or `POST /rotate` with the same signed payload rotates the credential and disconnects the old tunnel. No caller chooses a fresh hostname. Host assignments and revocation survive restart.

`POST /revoke` takes `hostname` and the device's bearer credential. Revocation is permanent for that key. `POST /policy` requires the operator bearer token and accepts `hostname`, `limits` (`connections`, `bytes_per_second`, `monthly_bytes`, all positive), `disabled`, and `revoked`. Policy changes disconnect existing streams; disabling refuses subsequent attachment. A disabled device can prove ownership and rotate, but cannot attach until the operator reenables it.

State is an atomically replaced, fsynced mode-0600 JSON file containing public keys, credential hashes, policies and usage counters. One process owns each state file. Every forwarded chunk reserves durable quota before writing; failed transfers may therefore consume quota, but cannot exceed it. Both ciphertext directions, including the ClientHello, count against one UTC calendar-month allowance and one shared pacing schedule. Admission limits active public connections per device. Budgets default to 32 connections, 1 MiB/s and 10 GiB/month. Usage resets lazily at a UTC month boundary. Reenrollment and credential rotation preserve it.

T13 integrates through `relay.Server.Attach(hostname, credential, Tunnel)`, where `Tunnel.Open(context.Context)` returns one independent bidirectional raw byte stream. Open must respect cancellation, and Close must unblock I/O. Attach verifies the current credential; replacement, rotation, revocation, policy changes and shutdown cancel active streams. The device-side transport must be authenticated and encrypted. T12's lab adapter uses local TCP connections to two independent TLS origins. The standalone command has no network tunnel registration endpoint until T13 supplies the authenticated multiplexed control transport. No multiplexer or new dependency is included.

The sim scenarios verify two origins with individually trusted synthetic certificates, unknown SNI, ciphertext-only relay boundary buffers, key possession, stable assignment after restart, credential rotation/revocation, owner isolation, connection and byte limits, persistent quota and the kill switch. The fixture CA is generated locally rather than issued by Pebble (not installed). Buffer observation proves the relay boundary contains ciphertext; it is not an independent process heap/log scan. These two acceptance limitations remain recorded in features.yaml. Public deployment, DNS and certificate issuance belong to T13 and later tickets; no macOS grants are needed.

## Outbound transport and Mac certificates (T13–T15)

The Mac keeps one authenticated TLS WebSocket to the control API, carrying smux v2 streams (MIT). The relay opens a stream for each admitted public ClientHello. A single-use, one-minute server nonce signs the device host, credential and action using Ed25519; credentials alone cannot attach a tunnel or publish DNS. Per-session buffers are bounded. Health frames run every second, with a three-second dead-peer timeout and reconnect backoff from 100 ms to at most 1.6 s. Public TLS terminates in `bridge`; the relay handles ciphertext.

The relay backend enrolls once, stores its device key and credential under the private bridge home, and retains its hostname across reconnects. `APPLE_BRIDGE_RELAY_URL` selects the HTTPS control origin; the default is `https://ab.lexaai.tech`. DNS-01 publishes only `_acme-challenge.<enrolled-host>` through signed control requests. The action signature binds the TXT value. Account and certificate private keys stay under `<home>/remote/`, mode 0600. Certificates renew when at most 30 days remain; an in-memory TLS callback adopts the replacement without listener restart.

`--domain` requires both the host CNAME and challenge CNAME. Pending status names the exact missing records. The relay verifies these records independently before persisting an alias. Requested certificate fingerprints are retained; the relay checks crt.sh hourly and reports unexpected fingerprints or unavailable checks through signed status requests. This is best-effort aggregator monitoring, not an independent CT log verifier. It has no live completeness certification yet.

`deploy/relay` supplies the hardened systemd service and Google Cloud DNS adapter. The VM uses metadata service-account tokens; no downloaded service-account key is used. The deployed service uses `--control-acme` for trusted apex control TLS and automatic renewal. Delegation, public A records, DNS OAuth scope and IAM are qualified; device certificates terminate on the Mac. DNS publication waits for public TXT propagation before ACME validation. Pebble issuance, renewal, private key placement and custom-name issuance pass sim with real DNS-01 validation. Four-second lab stream proof covers the two-second inactivity threshold, and listener replacement checks reconnection under five seconds.

Review regression coverage: RELAY-OWN-DOMAIN submits signed domain registrations to the relay, rejects forged ownership and replay, checks both missing CNAME records, and routes custom-name TLS through an authenticated device tunnel. CT monitoring checks the assigned and custom names independently and aggregates their warnings, including an unexpected assigned-name certificate when custom-name monitoring is unavailable.
