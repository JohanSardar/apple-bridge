# Vision queries

`vision.ocr` accepts exactly one of `data_base64` or an absolute local `file` path with `allow_file: true` and optional `languages` in query args. It returns `text`, `language` (BCP-47 or `und`) and `lines` containing text, confidence and normalized Vision boxes with a bottom-left origin. Vision performs accurate recognition with automatic language detection. Encoded images are limited to 8 MiB and decoded geometry to 40 million pixels.

`pdf.text` accepts exactly one of `data_base64` or an absolute local `file` path with `allow_file: true` and returns one-based `pages` and `page_count`. `pdf.search` additionally accepts nonempty `text` and returns case-insensitive matches with one-based pages, UTF-16 offsets and lengths. Locked documents reject. Documents are limited to 8 MiB, 1,000 pages, 200,000 extracted UTF-8 bytes and 10,000 matches.

`vision.ocr`, `pdf.text` and `pdf.search` also accept `blob: {query_id, digest}` as the sole document input. Alternatively, `blob: {collection, record_id, digest}` resolves a blob referenced by a currently visible record (including generated PDF artifacts). Mixed handle forms reject. The gateway resolves only an unexpired query blob lease owned by the caller with its original read grant still held, bounds the bytes to 8 MiB, and forwards inline bytes to the Helper. A digest alone grants no access. Blob inputs never expose a gateway file path.

These are transient queries. OCR and extraction declare no replicated collections, retain no baseline, schedule no idle polling and require no TCC grants. Gateway authorization uses separate `vision:read` and `pdf:read` scopes; corresponding write scopes are reserved. Evidence records assertions only. Synthetic fixture generation is reproducible with `xcrun swift lab/fixtures/vision/generate.swift "$PWD/lab/fixtures/vision"`.

The simulator recognizes only the generated fixtures and returns unavailable for other valid inputs. It never performs OCR. Native recognition uses Vision, NaturalLanguage and PDFKit. No third-party implementation was copied.

`pdf.annotate` is a `pdf:write` command accepting the same document inputs and an `annotations` array (1–100 entries). Each annotation has a one-based `page`, `type` (`note` or `highlight`), `text` (up to 4,096 UTF-8 bytes; required for notes), and a rectangle with nonnegative `x`, `y` and positive `width`, `height` in PDF page points with a bottom-left origin. Rectangles must fit the page. The command produces a new PDF without changing the input. PDFKit reopens the output and verifies annotations before publishing `pdf.artifact` with a blob reference and annotation count. The command is observed only after its artifact capture is committed. Large inline or resolved blob inputs are staged privately for the command and cleaned up afterward. Replicas retain artifact metadata without prefetching PDF bytes; scoped blob reads fetch bytes on demand. The simulator supports the synthetic single-page fixture only.
