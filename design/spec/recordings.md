# Voice Memos and voicemail

Rust captures both sources through read-only SQLite WAL snapshots. Complete scans reconcile changed rows and confirmed absences. UUID native keys are preferred; fallback row keys are scoped to the database generation. Missing stores report unavailable with reason `store not present`; incompatible required schemas cannot establish absence. No write operations are advertised.

Voice Memos reads `CloudRecordings.db`, folder records, local M4A audio and embedded timed transcripts. Voicemail reads the macOS 26 FaceTime message store at `~/Library/Group Containers/group.com.apple.FaceTime/com.apple.facetimemessagestored/Data Store/FaceTimeMessageStore-local.sqlitedb`. Rows with `ZDATEDELETED` are excluded when that column exists. Missing optional provider, mailbox, message-type, transcript or file-type columns do not hide metadata.

Voicemail transcripts decode bounded NSKeyedArchiver data in `ZTRANSCRIPT`, without instantiating native objects. Carrier archives contain `transcriptionString`, segments and optional confidence; FaceTime archives can contain an array of segments. Local audio is addressed by the record UUID under `Assets/<first two uppercase UUID characters>/<uppercase hyphenated UUID>.<ZFILETYPE>`. AMR, M4A and audio-only MOV are supported case-insensitively; FaceTime video is not exposed as audio. Audio stays byte-for-byte original, is confined to the source root, and is copied into private content-addressed staging. Dataless files are not downloaded. Asset arrival, replacement and removal trigger reconciliation without requiring a database change. Voicemail scans once on restart instead of trusting old input signatures, rebuilding asset tracking and upgrading existing metadata-only captures.

The [voicemail API contract](../../docs/reference/voicemail.md) defines the fields returned through MCP and `bridge read voicemail`. Blob reads use the existing authorization, size bounds, SHA-256 validation and replication paths. Transcript and audio content, phone numbers and source UUIDs must never enter proof output or lab evidence.

Real-store proof uses an independent Python count/hash oracle and the Rust reader on a private snapshot. Run `python3 packaging/dev/prove-voicemail.py /path/to/voicemail-proof` on an authorized Mac; compile the example with `rust/check.sh build --locked -p ab-native --example voicemail-proof` on an authorized build host. The proof reads Apple's database/WAL and local audio only, works entirely in a private temporary directory, cleans it on exit, and prints aggregate counts and hash-equality booleans. A missing/empty store, inaccessible data, changing snapshot or missing audio proof is unverified, not a pass. This does not qualify signed Helper/TCC attribution or the live gateway.
